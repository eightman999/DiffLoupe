# DiffLoupe 比較アルゴリズム仕様書(Swift macOSネイティブ版 v1)

本書は、既存実装である C++/Qt 版([src/core/comparator.cpp](../legacy/cpp/src/core/comparator.cpp) /
[comparator.h](../legacy/cpp/src/core/comparator.h) / [diffresult.h](../legacy/cpp/src/core/diffresult.h))と
Python/PySide6 版([Python/comparator.py](../legacy/Python/comparator.py))のコード読解に基づき、
比較アルゴリズムの現行仕様を明文化し、Swift 版 v1 で採用する仕様を確定するものである。

読解対象コミット: `32c49dc`(master)

## 1. 既存実装の仕様

### 1.1 ディレクトリ走査

| 項目 | C++版 | Python版 |
|---|---|---|
| 走査方法 | `QDirIterator`(`Files \| Dirs \| NoDotAndDotDot`, `Subdirectories`)で再帰列挙(comparator.cpp:84-85) | `os.walk()` で再帰列挙(comparator.py:44) |
| 再帰深さ | 無制限 | 無制限 |
| ディレクトリのシンボリックリンク | 辿らない(`FollowSymlinks` 未指定) | 辿らない(`followlinks=False` 既定) |
| ファイルのシンボリックリンク | 比較対象。内容はリンク先を読む | 同左 |
| 隠しファイル(`.`始まり) | 既定で除外。`showHidden` で表示可(comparator.cpp:255-258) | 既定で除外。`show_hidden` で表示可(comparator.py:51) |
| 隠しディレクトリ | 除外を**意図**しているが不具合あり(後述 1.4) | サブツリーごと正しく除外(`dirs[:]` プルーニング、comparator.py:46-47) |
| 除外パターン | なし(隠しファイル規則のみ) | なし(同左) |
| ディレクトリ自体のエントリ化 | されない。ファイルのみ相対パスをキーに記録(comparator.cpp:90-109)。**空ディレクトリは結果に現れない** | 同左(comparator.py:49-58) |
| 対象フォルダ数 | N ≧ 2 に対応 | 同左 |
| エントリの照合キー | 基準フォルダからの相対パス(文字列完全一致) | 同左 |
| 結果の並び順 | `std::map` のキー順(QString の辞書順) | `sorted()`(辞書順、comparator.py:63) |

補足: `.git` と `.DS_Store` は「`.`始まり」規則により既定で除外されるが、
`node_modules` はどちらの版でも除外されない。

### 1.2 ファイル同一性の判定基準

両版とも同じ**2段階判定**である(C++版は `useMetadataFirst`(既定 true)で1段目を省略可)。

1. **突き合わせ**: 相対パスをキーに各フォルダのファイルを束ねる。
2. **片側のみ存在**: 内容比較を行わず「欠落」扱い。
   - C++版: `MissingInA` / `MissingInB`(comparator.cpp:140-154、diffresult.h:35-36)
   - Python版: ステータス算出されず、後段で空ハッシュ集合により「一致」となる**不具合**あり(後述 1.4)
3. **メタデータ一次比較**: **サイズが完全一致 かつ mtime が完全一致** → 「一致(メタデータ)」と判定し、**ハッシュ計算を行わない**(comparator.cpp:128-131、comparator.py:72-75)。
   - C++版は `QDateTime` の等値比較、Python版は `st_mtime`(float)の等値比較。
4. **ハッシュ比較**: メタデータ不一致の場合のみ、対象ファイルの **SHA-256** を
   **64KiB チャンクのストリーミング読み込み**で並列計算(C++: `QThreadPool`+`QtConcurrent`、
   Python: `multiprocessing.Pool`)。全ファイルのハッシュ値が1種類以下なら「一致」、
   2種類以上なら「差異」(comparator.cpp:238-247、comparator.py:105-116)。

**バイト単位の直接比較はどちらの版も行わない。**
タイムスタンプのみが異なる同内容ファイルはハッシュ比較により「一致」になる。
逆に「サイズと mtime が一致するが内容が異なる」ファイルは**誤って「一致(メタデータ)」と判定される**
(両版共通の設計上のリスク)。

### 1.3 進捗通知

- C++版: フェーズ単位の固定パーセンテージ(収集中0% → ハッシュ30% → 整理90% → 完了100%)+
  ハッシュ計算の件数進捗(n/m)をコールバック通知(comparator.cpp:37-75, 202-209)。
- Python版: comparator 自体は進捗通知を持たない(GUI 側ワーカーが管理)。
- キャンセル機構はどちらの comparator にもない。

### 1.4 既知の不具合(読解で確認したもの)

| # | 内容 | 該当箇所 |
|---|---|---|
| B1 | C++版: 隠しディレクトリのスキップに `it.next()` を誤用。`QDirIterator` はサブツリーの枝刈りができないため、**隠しディレクトリ配下のファイルは(ファイル名が`.`始まりでない限り)比較対象に含まれてしまう**。さらに直後のエントリを1件余分に読み飛ばすため、無関係なファイルが欠落しうる | comparator.cpp:90-94 |

### 1.5 C++版と Python版の相違点まとめ(両論併記)

| 項目 | C++版 | Python版 | Swift v1 での採用案 |
|---|---|---|---|
| 隠しディレクトリ除外 | 機能していない(B1) | サブツリーごと除外 | 除外はパターン方式に変更(§2.2)。プルーニングは Python 版方式(サブツリーごと) |
| 片側のみのステータス | `MissingInA`/`MissingInB` を明示 | 「一致」になる(B2) | C++版方式を採用し `leftOnly`/`rightOnly` を明示 |
| 読込エラーの扱い | 「一致」誤判定(B3) | 同左(B3) | 新設の `error` ステータスで明示(§2.3) |
| 一次比較 | サイズ+mtime(設定で無効化可) | サイズ+mtime(固定) | **mtime を判定に使わない**(§2.3、意図的変更) |
| 進捗・キャンセル | 進捗のみ | なし | 進捗+キャンセル両対応(§2.5) |

## 2. Swift 版 v1 の採用仕様

### 2.1 前提

- 比較対象は**左右2フォルダ**に限定する(既存は N≧2 だが、v1 の製品方針は2ペイン比較)。
- フォルダは `NSOpenPanel` 経由でのみ指定する。
- 実装は Foundation / CryptoKit / Swift Concurrency のみを使用(外部依存ゼロ)。

### 2.2 ディレクトリ走査

- 各フォルダを再帰走査する。深さ無制限。
- **ディレクトリのシンボリックリンクは辿らず、エントリとしても記録しない**(既存両版と同じ)。
- **ファイルのシンボリックリンクは比較対象とし、内容はリンク先を読む**(既存両版と同じ)。
  リンク切れは読込エラーとして `error` 扱い。
- **隠しファイル・隠しディレクトリは比較対象に含める**(既存既定からの変更)。
  - 理由: 本製品の用途(納品物・バックアップの突き合わせ)では全ファイルの把握が重要。
    ノイズは下記の既定除外パターンで抑制する。既存の `showHidden` トグルは採用しない。
- **除外パターン**: 名前が `.git` / `.DS_Store` / `node_modules` に完全一致する
  エントリを既定で除外する(ディレクトリの場合はサブツリーごと除外)。
  設定でこの既定除外を一括オン/オフできる。加えて**ユーザー定義の除外glob**を
  設定画面から指定できる(§2.9)。
- **ディレクトリもエントリとして記録する**(既存からの拡張)。
  これにより空ディレクトリや片側のみのディレクトリも「左のみ/右のみ」としてツリーに表示される。
- 照合キーは相対パス。**NFC 正規化した上で照合する**(既存は未対応。macOS の NFD と
  外部由来 NFC の混在で同名ファイルが別エントリになる事故を防ぐ)。実ファイルアクセスには
  各側で列挙時に得た元の URL を用いる。
- 大文字小文字はファイルシステムが返した名前をそのまま用いる(大小のみ異なる名前は別エントリ)。

### 2.3 ファイル同一性の判定(段階判定)

相対パスで突き合わせた各エントリについて、次の順で判定する。

1. **片側のみ存在** → `leftOnly` / `rightOnly`(内容比較なし)。
2. **種別不一致**(片方ファイル・片方ディレクトリ)→ `different`。
3. **両側ファイル・サイズ不一致** → `different` を確定(ハッシュ計算を省略)。
4. **両側ファイル・サイズ一致** → 両ファイルの **SHA-256(64KiB チャンクのストリーミング)** を計算し、
   - ハッシュ一致 → `identical`
   - ハッシュ不一致 → `different`
5. いずれかの段階で読み込み・stat に失敗 → `error`(B3 の修正)。

**既存からの意図的変更(重要)**: 既存両版の「サイズ+mtime 一致 → 同一(ハッシュ省略)」は
内容相違の見逃しリスクがあるため、**v1 では mtime を判定に一切使わない**。
- サイズ不一致 → 内容は必ず異なるため、ハッシュ省略は安全(高速化)。
- サイズ一致 → 必ずハッシュで確認する(確実性優先)。
- 性能は「サイズ不一致の早期確定」+「ハッシュ計算の並列化」(§2.5)で担保する。
  メタデータ高速モードの再導入は v2 以降の検討事項として WORK_LOG に記録する。

ハッシュアルゴリズムは既存両版と同じ SHA-256(CryptoKit)。チャンクサイズも同じ 64KiB。

### 2.4 分類と表示

ファイルの分類は次の5種:

| ステータス | 意味 | 由来 |
|---|---|---|
| `identical` | 内容一致(ハッシュ一致) | 既存の「一致」 |
| `different` | 内容相違 / 種別不一致 | 既存の「差異」 |
| `leftOnly` | 左フォルダのみに存在 | 既存の `MissingInB` |
| `rightOnly` | 右フォルダのみに存在 | 既存の `MissingInA` |
| `error` | 読込不可・stat 失敗 | 新設 |

ディレクトリの表示ステータスは子孫の集約とする:
- 片側のみに存在するディレクトリ → `leftOnly` / `rightOnly`
- 両側に存在し、全子孫が `identical` → `identical`
- それ以外(子孫に相違・片側のみ・エラーを含む)→ `different`(=「差分を含む」)

ツリーの同一階層の並び順は**ディレクトリ優先、名前昇順**(Finder 互換の
`localizedStandardCompare`)。

### 2.5 並列化・進捗・キャンセル

- 走査とハッシュ計算はメインスレッド外で実行する(Swift Concurrency)。
- ハッシュ計算は `TaskGroup` で並列化し、同時実行数は `min(8, 論理コア数)` に制限する。
- 進捗は2フェーズで通知する: 走査(発見エントリ数)、内容比較(完了 n / 対象 m)。
- ユーザーはいつでもキャンセルできる(`Task` キャンセルを各ループで検査し、
  `CancellationError` で中断する)。既存にはない機能。

### 2.6 テキスト差分表示(v1 新規仕様)

フォルダ比較とは独立した、選択ファイルの表示用仕様。

- **行単位**の差分。`CollectionDifference`(Foundation 標準、Myers 法)で算出する。
- 表示は横並び2ペイン。行の対応付けは、連続する削除ブロックと挿入ブロックを
  index 順にペアリングして「変更行」とし、余りを純粋な「削除行」「追加行」とする。
  配色: 追加=緑系、削除=赤系、変更=黄系ハイライト。
- 文字コードは**主要エンコードを自動判定**する(v1.2 で UTF-8 固定から拡張)。判定順序:
  1. BOM 判定(UTF-32 BE/LE → UTF-16 BE/LE → UTF-8 の順。4バイトBOMを先に見る)
  2. BOM 無しの場合、先頭 8KiB に NUL バイトを含めばバイナリ扱い(従来挙動を維持)
  3. 全バイトが 7bit かつ ESC(0x1B) を含む場合は ISO-2022-JP としてデコード試行
     (ISO-2022-JP は 7bit エンコードで UTF-8 としても常に有効なバイト列になるため、UTF-8 より先に判定する)
  4. UTF-8 厳密デコード(BOM 無し有効 UTF-8 は従来と完全同一の結果になる=後方互換)
  5. Shift_JIS / EUC-JP ヒューリスティック判定(`NSString.stringEncoding` API)
  全て失敗したファイルは「バイナリファイル」と表示し、差分表示しない。
  判定したエンコード名(例: "UTF-8", "Shift_JIS", "UTF-16 LE")は差分ビューのヘッダに左右それぞれ表示する。
- 行分割は LF 基準とし、**表示・行比較時のみ行末の CR を除去する**(CRLF ファイル対策)。
  注意: フォルダ比較(§2.3)はバイト厳密なので、改行コードのみが異なるファイルは
  「内容相違」に分類される。これは仕様である(差分ビューでは行内容の違いとして見えない場合がある)。
- 巨大ファイル保護: 左右合計 40,000 行を超える場合は差分計算を行わず、その旨を表示する
  (Myers 法は相違が大きいときに計算量が増大するため)。また 32MiB を超えるファイルは
  読み込みを行わず「大きすぎる」と表示する(メモリ保護)。
- 内容比較モード(§2.9)が有効な場合、**差分計算には正規化済みの行を使い、表示には元のテキストを使う**。
  大文字・空白・行末 CR などの正規化設定に関係なく、ユーザーは元のファイル内容を確認できる
  (行の対応付けだけが正規化規則に従う)。

### 2.7 git リポジトリ比較(v1.2 新規仕様)

選択フォルダが git 作業ツリー内にある場合、各サイド独立に比較対象の ref を選択できる。

- フォルダ選択時に `git rev-parse --show-toplevel` でリポジトリを検出し、検出時のみ
  ref 選択メニュー(「作業ツリー」(デフォルト) / ブランチ・タグ一覧 / 任意 ref 手入力)を表示する。
  非リポジトリでは UI・挙動とも従来と完全に同一。
- ref 選択時は `git archive <ref> | tar -x` で一時ディレクトリにスナップショットを実体化し、
  その URL を既存の `FolderComparator` にそのまま渡す(エンジン側は git を関知しない)。
  `checkout` 方式は作業ツリーを汚すため使わない。git/tar の引数は配列渡し(シェル経由禁止)。
- スナップショットは比較結果の詳細表示(テキスト/画像 diff)が参照し続けるため、
  比較成功時は破棄せず保持し、次回比較開始時に前回分を削除する。失敗・キャンセル時は即時削除する。
- ref が存在しない等の git エラーは既存のエラー表示経路でユーザー向けメッセージとして表示する。
- gitバイナリは `/usr/bin/git` を使用(Xcode Command Line Tools 前提)。App Sandbox は無効のため
  Process 起動に制約はない。

### 2.8 既知の制限・v2 以降への持ち越し

- メタデータ(mtime)による高速一致モードのオプション化。
- ハードリンク・FIFO 等の特殊ファイルは対象外(走査時に通常ファイル・ディレクトリ以外はスキップ)。
- 同一ボリューム上の APFS クローンの高速判定(clonefile 検出)は行わない。

### 2.9 比較オプション(内容比較モード・ユーザー除外glob・リネーム検出)(v1.3 新規仕様)

設定画面(UserDefaults/AppStorage で永続化)から指定でき、次回の比較から反映される。
設定キーは `AppModel` に集約し、UI・比較実行・テストで共用する。

#### ユーザー定義の除外glob

- 1行1パターンで入力し、空行・前後空白・重複・空パターンを正規化する(`AppModel.normalizeExcludePatterns`)。
- 区切りなしのパターンは**ファイル名(最終パス成分)**に、区切りありのパターンは**相対パス**に照合する。
  ディレクトリに一致すればサブツリーごと枝刈りされる(走査時点でスキップ)。
- 対応ワイルドカード: `*`=セパレータをまたがない任意列、`?`=セパレータをまたがない1文字、
  `**`=セパレータをまたぐ任意列(0個以上)。
- 既定の除外(.git / .DS_Store / node_modules)とは独立して適用される。

#### 内容比較モード(ContentComparison)

フォルダ分類(FolderComparator)と詳細差分(LineDiff)の**両方で同じ規則を共用**する。

- `ignoreLineEndings`(改行コード無視): CRLF/CR/LF を同一視。
- `ignoreTrailingWhitespace`(行末空白無視): 行末のスペース・タブを無視。
- `normalizeWhitespace`(連続空白正規化): タブ・連続空白を単一スペースに正規化(行頭行末も除去)。
- `ignoreCase`(大文字小文字無視)。
- 全てオフ = **厳密比較**(既定・後方互換)。このときフォルダ分類は従来どおり
  「サイズ → SHA-256」で、コストも従来と同じ。
- 正規化モードではサイズ不一致でも「正規化後に一致しうる」ため、必ず内容比較する。
  バイナリ(NUL 含む)や UTF-8 としてデコード不能なファイルは**バイト厳密比較にフォールバック**し、
  正規化による内容相違の見逃しを防ぐ(保守側)。
- **巨大ファイル保護**: `Options.maxNormalizationCompareBytes`(既定 64MiB)を超えるファイルは
  `Data(contentsOf:)` による一括読込の正規化比較をせず、**バイト厳密(ストリーミングハッシュ/サイズ)で判定**する。
  OOM を起こさないことが目的で、超過分は「サイズ不一致 → 相違」「サイズ一致 → ハッシュ判定」となる。

#### リネーム/移動候補の検出(detectRenames)

- 片側のみのファイルを内容ハッシュで束ね、対向側の片側のみファイルと内容一致するものを
  `ComparedEntry.renameCandidate` として載せる(既定オフ・有効化で追加の並列ハッシュ走査が入る)。
- `DiffStatus` は変更せず、1対1対応なら「確定」、同内容が複数ある場合は「候補(件数付き)」として UI 表示する。
- 検出フェーズは `ComparisonProgress.renames(done:total:)` で進捗通知する(キャンセル対応・
  CancellationError は読み込みエラーと区別して再送出する)。

#### 詳細差分ビューのメタデータ表示

- 左右のサイズ・変更日時・POSIX パーミッションをヘッダーに表示する。
- 片側のみファイルのリネーム/移動候補は「確定/候補 + 相手パス」を表示する。

### 2.10 テキスト詳細差分UX（行内差分・差分ナビゲーション・検索・コンテキスト折りたたみ・水平スクロール）(v1.4 新規仕様)

[WinMerge公式マニュアル](https://manual.winmerge.org/en/)のテキスト比較UXを参考に、選択ファイルの横並び詳細差分表示を拡張する。

#### 行内差分(InlineDiff)

- `.modified` 行の左右テキストに対し、LCS(最長共通部分列)動的計画法で文字単位の変更範囲を算出し、UIで強調表示する。
- 左右テキストが `nil`・空文字でも安全に処理し、`Character` 単位でUnicode境界を壊さない。
- 左右合計が1,200文字を超える行は計算量・メモリ保護のため行内ハイライトを省略し、行単位差分表示は維持する。

#### 差分行ナビゲーション

- `.added` / `.removed` / `.modified` 行を対象に、前後ボタンと `⌘↓` / `⌘↑` で移動する。
- 未選択状態(`diffIndex == nil`)では表示を `—/N` とし、「次の差分」は先頭へ、「前の差分」は末尾へ移動する。

#### 検索とコンテキスト折りたたみ

- 検索対象は左右いずれかの**元テキスト**。片側のみの行も安全に検索し、大文字小文字の区別を切り替えられる。空クエリは解除する。
- 連続する `.context` 行が5行以上の場合、1行の「N行を表示」ヘッダーに折りたたむ。クリックまたは「全行表示」で展開できる。
- 検索ヒットまたは差分ジャンプの対象行が折りたたみグループ内にある場合、そのグループを自動展開する。

#### 長い行

- 2ペインの行対応と行番号・色分けを維持しつつ、共通の水平スクロール領域とセルの最小幅を使って長い行を横方向に読めるようにする。

#### 検証状況

- 確認済み: 行内差分、1,200文字上限、nil/Unicode安全処理、折りたたみ閾値5、未選択ジャンプ、検索ヒットのグループ展開ロジック。自動テストは107件全件成功。
- 未検証: GUIの見映え、キーボードショートカットの実機操作感、アニメーション付きスクロール追随、ライト/ダークモードでの色の視認性。

### 2.11 左右交換・Finder D&D・比較履歴・レポート出力(v1.5 新規仕様)

[WinMerge公式マニュアル](https://manual.winmerge.org/en/)の操作性およびエクスポート運用を参考に、左右フォルダの交換、ドラッグ&ドロップ入力、比較履歴、レポート出力を実装する。

#### 左右交換(`⌘⇧S`)

- `AppModel.swapSides()` で左右のフォルダURL・検出済み `GitRepository`・左右のGit refを一括交換する。
- 比較実行中(`phase.isRunning`)はno-opとする。交換時は比較結果・選択・エラーを破棄し、結果が参照していた一時Gitスナップショットをクリーンアップする。

#### Finderフォルダドラッグ&ドロップ

- 左右のフォルダ選択エリアは `.onDrop(of: [.fileURL])` で単一フォルダを受け付ける。
- 複数項目、ファイル、存在しないパス、比較実行中は拒否する。受理したURLはシンボリックリンクを解決し、既存のフォルダ適用経路でGitリポジトリ検出とref初期化を行う。

#### 比較履歴

- 左右パス・左右Git ref・比較日時を `RecentComparison` として `UserDefaults` にISO8601 JSON保存する。
- 最大10件で、左右パスの順序が一致する同一ペアは先頭へ移動する。壊れた保存データは空履歴として安全に無視する。
- 履歴復元時に左右が実在するディレクトリでない場合は復元せず、UIでも選択不可とする。

#### レポート出力

- `ComparisonResult` をHTML/CSV/JSON/Markdownへ変換し、`NSSavePanel`で保存する。初期名はUTCの `DiffLoupe-report-YYYYMMDD-HHMMSS.<ext>` とする。
- 既存ファイルは `NSAlert` で明示確認し、キャンセル時は書き込まない。
- JSONはpretty print + sorted keys、日時はUTC ISO8601、CSVはカンマ・引用符・改行をRFC4180相当に引用、HTMLはスタンドアロンのサマリ/詳細テーブルとステータス別配色を持つ。

#### PRO構成と検証状況

- Free/Proの制限とライセンス処理は既存の `#if PRO` 配布構成に依存する。通常のFreeプロジェクト設定ではProソースを登録しない構成を維持する。
- モデル・ストア・レポートフォーマッタは自動テストで確認済み。Finder D&D、ショートカット、NSSavePanel/上書き確認のGUI実機挙動は未検証である。

### 2.12 CLI(diffloupe)とWinMerge互換運用(v1.6 新規仕様)

[WinMerge公式日本語マニュアルのコマンドライン仕様](https://manual.winmerge.org/ja/Command_line.html) と
[公式Command_line.xml](https://github.com/WinMerge/winmerge/blob/master/Docs/Manual/Japanese/Command_line.xml)
を参照し、GUIを使わない比較・CI運用向けの`diffloupe`をSwiftPMで提供する。

#### 2.12.1 パッケージ構成

- `SwiftUI/Package.swift`はmacOS 13+を対象とする。
- `DiffLoupeCore`はGUI/AppKit/Pro依存を除いた既存のEngine/Modelsを再利用し、比較判定を二重実装しない。
- `DiffLoupeCLI`は引数解析・実行制御・出力・終了コードを持ち、`CLI/main.swift`はシグナル処理と終了コード返却だけを行う。

#### 2.12.2 再帰制御

- WinMergeの仕様に合わせ、CLIの既定は非再帰でルート直下だけを比較する。
- `-r`、`--recursive`、`/r`はサブディレクトリを再帰比較する。
- `--no-recursive`、`/r-`は非再帰を明示する。
- GUI側の`FolderComparator.Options`既定値はtrueのままとし、既存アプリの再帰挙動を変えない。

#### 2.12.3 WinMergeスラッシュスイッチ

| スイッチ | CLIでの扱い |
|---|---|
| `/r`、`/r-` | 再帰オン/オフ |
| `/or <path>` | レポートファイル出力。拡張子が未知の場合はHTML |
| `/enableexitcode` | 終了コードを0=一致、1=差異、2=エラーへ写像 |
| `/x`、`/xq` | CLIの進捗抑止へマップ。サマリ出力までは抑止しない |
| `/u`、`/ul`、`/um`、`/ur` | GUIの履歴制御のため受理のみ(no-op) |
| `/wl`、`/wm`、`/wr` | GUIの読み取り専用指定のため受理のみ(no-op) |
| `/minimize`、`/maximize`、`/noninteractive` | GUI制御のため受理のみ(no-op) |
| `/dl`、`/dm`、`/dr` | ラベル値を消費するが、CLI表示・レポートには反映しない |

既知のスイッチと一致しない`/tmp/...`等の絶対POSIXパスは位置引数として扱う。

#### 2.12.4 出力と終了コード

- `--format`または出力拡張子でHTML/CSV/JSON/Markdownを選択する。レポートを標準出力へ出す場合、
  レポートはstdout、進捗と人間向けサマリはstderrへ分離する。
- `--output`と`/or`は親ディレクトリが存在する新規ファイルだけを受け付け、既存ファイルの上書きを拒否する。
- 通常の終了コードは`0`=全ファイル一致、`1`=差異/片側のみ/読み込みエラー、`2`=引数・パス・出力エラー、
  `3`=比較処理エラーまたはキャンセル。
- `/enableexitcode`指定時は上記の`2`と`3`をWinMerge相当の`2`へ縮約する。これは互換運用のための写像であり、
  WinMergeの完全なドロップイン実装ではない。

#### 2.12.5 検証と制限

- 現ワークツリーではSwiftPMの`swift test`が187件0失敗。CLI統合、Core比較、構造化比較、Hex、3-wayを含む。
- `Scripts/verify_cli.sh`は終了コード19項目とレポート内容2項目を検証し`ALL PASSED`。
- Xcodeの`xcodebuild test`は212件0失敗。`xcodebuild build`も成功している。
- 3-wayマージ適用、GUIウィンドウ状態、Finder/NSSavePanelの実機操作は未検証または本仕様の対象外である。

### 2.13 画像比較ビューアーの拡張(v1.7 新規仕様)

[WinMerge公式日本語マニュアルの画像比較](https://manual.winmerge.org/ja/ImageCompare.html)を参考に、
既存の5つの画像比較モードを維持したまま表示操作を拡張する。

#### 2.13.1 共有ImageViewport

- 左右、重ね合わせ、ブリンク、差分、スライスの各モードで同じ`ImageViewport`を共有する。
- 倍率は0.25x〜4.0x。倍率スライダー、拡大/縮小ボタン、フィット表示へのリセットを提供する。
- ドラッグでパンし、`MagnificationGesture`でピンチズームする。ビューポート変更では画像比較を再実行せず、
  読み込み済みのCGImageを再利用する。
- 左右の画像寸法が異なる場合は共通キャンバスを表示基準にする。表示モードを切り替えたときはパン位置を
  リセットし、共有オフセットが別レイアウトへ持ち越されることを防ぐ。

#### 2.13.2 閾値と再計算

- 差分表示の色差閾値は0〜255の整数で指定する。既存エンジンのピクセル距離判定を利用する。
- 閾値スライダーの変更は400msデバウンスし、操作中の各ステップで比較タスクを起動しない。
- 閾値確定後は差分結果を再計算する。大画像の既存ダウンサンプリング保護は維持する。

#### 2.13.3 レイアウト

- 画像比較ツールバーは横スクロール可能とし、表示モード、オーバーレイ不透明度、閾値、スライス境界、
  ズーム操作を狭いウィンドウでも失わない。
- 画像メタデータの警告は、寸法・ファイルサイズ・形式・差分統計のGrid下に独立行として表示する。

#### 2.13.4 検証状況と制限

- 自動検証済み: 現ワークツリーのXcode 212件0失敗、SwiftPM 187件0失敗、画像エンジンの微小色差閾値境界テスト。
- 未検証: macOS実機でのピンチ、ドラッグパン、スライス境界ドラッグ、モード切替時の体感、狭幅ツールバーの
  横スクロール。画像比較の閾値変更はデバウンス後に再計算するため、操作中に即時反映されない。

### 2.14 構造化比較エンジン(v1.8)

`StructuredNormalizer`は、構造化テキストの表記揺れを比較時だけ決定論的な形式へ正規化する。
既定モードは`disabled`で、従来の厳密比較を維持する。

- 対応モードは`disabled`、拡張子で判定する`automatic`、明示的な`json` / `xml` / `csv`。
  CSVモードは`.csv`と`.tsv`を扱う。
- JSONはオブジェクトのキーをソートし、配列順は保持する。浮動小数点値は往復可能な文字列表現を使い、
  近接する値を丸めて同一化しない。
- XMLは属性順をソートし、インデントだけの空白ノードを除去して整形する。CSV/TSVは引用符と区切りを
  解釈し、列幅を揃えた比較用テキストへ変換する。
- 8MiBを超える入力はパースせず、UTF-8 BOMは正規化前に除去する。左右のどちらか一方でも正規化に失敗した
  場合は、成功側のカノニカル文字列と失敗側のraw文字列を混在させず、両側を通常比較へ戻す。
- この正規化はフォルダ分類とCLIの構造化比較に適用する。3-wayおよび通常の詳細行差分は、行ベースの
  `ContentComparison`だけを判定に使用し、表示は原文を保持する。

### 2.15 Hexバイナリ比較(v1.9)

テキストとして扱えないファイルを、読み取り専用のHex表示で比較する。

- 16バイト/行でオフセット、Hex値、ASCII(印字可能範囲以外は`.`)を表示し、差分バイトを強調する。
- 8MiBを表示上限とし、超過時は`truncated`を立てて未比較範囲があることを表示する。
- 比較結果の表示だけを提供し、バイナリの編集・保存は行わない。

### 2.16 フィルタ集合とプリセット(v2.0)

`FilterSet`は比較対象をglobで絞り込む。エクスクルードはインクルードより優先する。

- 区切りなしのパターンは最終ファイル名、区切りありのパターンはNFC正規化済み相対パスへ照合する。
- `*`は区切りをまたがない任意列、`?`は1文字、`**`は複数階層をまたぐ任意列を表す。
- インクルードが空なら全ファイルを対象とし、非空なら一致するファイルだけを対象とする。ディレクトリは
  ネストした一致ファイルへ降下できるよう、インクルードだけでは枝刈りしない。
- 組み込みプリセットはソース管理、ビルド成果物、Web/Node.js、macOSメタデータを用意し、opt-inで有効化する。

### 2.17 フォルダ変更監視と自動再比較(v2.1)

設定で明示的に有効化した場合だけ、作業ツリーのフォルダをポーリング監視する。

- 既定間隔は1秒。相対パス、ファイル種別、サイズ、更新日時のスナップショットを比較し、変更を検知すると
  自動再比較する。監視開始時の初回スナップショットは通知しない。
- 比較中の変更はpendingとしてまとめ、比較完了後に一度だけ再比較する。
- 無限連鎖を防ぐため、連続自動再比較は3回で一時停止し、手動比較または設定の再ONで復帰する。
- Git refを選択した側は一時スナップショットとの比較になるため、その作業ツリーは監視しない。両側がrefの
  場合は監視しない。
- 本実装はポーリングであり、FSEventsの即時通知、同一サイズ・同一更新日時の内容変化、シンボリックリンク先の
  追跡は対象外である。監視は読み取り専用で、ファイルを変更しない。

### 2.18 安全なコピー計画プレビュー(v2.2)

`SyncPlan.make`は`ComparisonResult`から、左→右または右→左の計画を純粋関数で生成する。

- 片側のみのファイルは`copyFile`、片側のみのディレクトリは`createDirectory`とする。
- 両側に存在する差分は`conflict`、反対側のみの項目は削除しないため`preservedDestination`、比較エラーは
  `blocked`とする。一致項目は計画から省略する。
- 計画項目には相対パス、コピー元/先、バイト数、理由を持たせ、UIはサマリとテーブルを表示する。
- **適用処理は提供しない**。コピー、削除、上書き、権限変更、リネームの実行は行わず、読み取り専用プレビューに限定する。

### 2.19 読み取り専用3-way差分(v2.3)

共通祖先`base`と左右のテキストを比較し、マージ前の変更関係を3列で確認する。

- 状態は`unchanged`、`leftChanged`、`rightChanged`、`bothChangedSame`、`conflict`。
  左右の変更が同じ場合は`bothChangedSame`、異なる場合は`conflict`とする。
- 挿入・削除・置換を含む編集単位をbase行を軸に整列し、左右でハンク境界が異なる変更も同じbase行へ結合する。
  表示値は原文(行末CRを含む)、判定値だけ`ContentComparison`で正規化する。
- base/left/rightの合計40,000行を上限とし、超過または表示行と比較行の対応が取れない場合は計算を中断して警告する。
- UIはNSOpenPanelで3ファイルを選択し、状態色、行番号、競合数、上限警告を表示する。
- **マージ適用・保存・編集は提供しない**。3-wayは読取専用の確認ビューである。

### 2.20 WinMerge互換性の範囲と検証

[Plugins](https://manual.winmerge.org/en/Plugins.html)、
